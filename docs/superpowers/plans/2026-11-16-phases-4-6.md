**Goal:** Payments with allocation, monthly A4 PDF statements (single, ZIP, combined), payment acknowledgments, email delivery, optional scheduled billing, reports, dashboard/calendar/settings, then hardening and hand-off.

**Spec:** `JT_Property_Management_MASTER_PROMPT.md` §6 (steps 5–7), §7–§11, §13–§15 + master plan Global Constraints + Phase 3 plan rules.

## Global Constraints (in addition to earlier phases)

- Integer centavos; ledger sign + increases debt, − decreases; posted entries immutable; corrections = reversal + audit.
- **Statement math (binding):** `previous_balance = ReceivableLedgerService::previousBalance(acc, period_start, [this cycle's invoice ids])`; `payments_and_credits_since` = Σ all non-charge entries (payment, credit, adjustment, refund, writeoff, reversal not linked to this cycle's invoices) with effective_date ≥ period_start up to the statement as-of; `current_charges` = invoice stored `current_charges_cents`; `total_due = previous + current + payments_and_credits_since` (never below shown as negative = "Credit balance"). Acceptance: 1,800 + 4,150 = 5,950; a ₱500 payment dated after period_start → 5,450, previous still 1,800.
- A bill is **Paid** only when allocations cover its charge; **Partially paid** when some; **Overdue** when unpaid past due_date (Asia/Manila). Never call a bill a receipt.
- Payment acknowledgment ≠ official receipt: PDF says "Acknowledgment of Payment — not a BIR official receipt".
- PDFs: server-rendered Blade, A4 portrait, `spatie/laravel-pdf` (Browsershot + local Chrome) with documented dompdf fallback; private `local` disk; authorized download routes only; issued statement PDFs stored immutably in `statement_snapshots` (path + totals JSON + sha256).
- Email: Laravel Mail, queued `afterCommit`; never from preview; skip with reason when no email / opted out; `email_deliveries` unique (invoice_id, kind, attempt_key) for idempotency; auto-send OFF by default.
- Staff: record payments (status `pending`) in assigned properties; owner approves, reverses, refunds, writes off.

## Phase 4 — Collections & statements

### Task 4.1: Payments + allocation
Tables: `payments` (billing_account_id, property_id, amount_cents >0, paid_on date, method enum cash|bank_transfer|gcash|maya|check|other, reference null (unique per method when present), payer_name, collected_by user, status pending|approved|reversed, proof_path null (private), notes, approved_by, ack_number unique null `ACK-{CODE}-{YYYY}-{seq5}`), `payment_allocations` (payment_id, ledger_entry_id (debit: charge or opening), amount_cents >0; Σ per payment ≤ payment; Σ per debit ≤ debit remaining).
`PaymentService`: `record(BillingAccount, array $data, User $by): Payment` (staff → pending, owner → approved immediately); `approve(Payment, User)` posts ONE `payment` ledger entry (−amount, effective_date = paid_on) and auto-allocates oldest-first unless manual allocations given; excess stays unallocated = credit (account balance negative); `allocate(Payment, array $manual)` owner; `reverse(Payment, string $reason)` reverses the ledger entry + deletes nothing (allocations marked via `reversed_at`); `refund(BillingAccount, int $cents, string $reason)` posts `refund` (+) only up to existing credit; `writeOff(LedgerEntry $debit, int $cents, reason)` posts `writeoff` (−) allocated to that debit.
Invoice payment status derived: `InvoiceStatusService::statusFor(Invoice): paid|partial|unpaid|overdue|void`.
Tests: partial pay; overpay → credit; oldest-first across opening + 2 invoices; manual allocation; reverse restores status; staff pending not on ledger until approved; refund > credit rejected; allocations never exceed debit.
UI: Collections page (unpaid/partial/overdue/credit filters, aging bucket column), "Record Payment" big button + modal (amount, method, reference, date, proof upload, allocation preview), payment detail.

### Task 4.2: StatementComposer + account statement

Tests: acceptance 5,950/5,450 with no double subtraction; credit balance shows negative; void invoice statement shows VOID; past-due amount = previous unpaid past due.

Tests: PDF bytes start `%PDF`, page count ≥1; long name/address/40 lines → multi-page; "Ñ ñ á ₱" present in the HTML; staff of another property → 403; snapshot unchanged after rent increase.

### Task 4.4: Bulk ZIP + combined PDF + print
